# EMA金叉爆发永续合约多头策略

## 策略定位

本策略用于数字货币 USDT 永续合约，只做多，默认使用 1 小时 K 线。

策略先寻找 EMA25 向上突破 EMA90，并要求 EMA7 同时位于 EMA25 和 EMA90 上方。金叉确认后不立即追涨，而是在附近指定周期内等待一根实体涨幅显著超过近期 K 线的爆发K线。爆发K线收盘确认后，策略提交多头入场意图，由 QuantDinger 在下一根 K 线开盘阶段处理。

对应的规则总览、空头镜像版本、图表指标和持仓管理关系见
[EMA 金叉爆发指标与策略指南](trading/EMA_CROSS_BURST_GUIDE_CN.md)。

## 默认合约池

策略源码顶部的 `CONTRACT_POOL` 是可交易合约池，默认包含：

- `Crypto:BTC/USDT@swap`
- `Crypto:ETH/USDT@swap`
- `Crypto:SOL/USDT@swap`

合约池属于 Strategy API V2 的策略清单，不是普通运行参数。修改合约池后必须重新保存、校验、回测和部署策略。

当前 QD 不允许动态品种池声明合约杠杆，因此本策略使用静态合约池。这样可以明确每个品种都是永续合约，并允许部署时选择不超过策略上限的杠杆。

## 入场条件

### 合格金叉

同时满足：

1. EMA25 从下向上突破 EMA90。
2. EMA7 高于 EMA25。
3. EMA7 高于 EMA90。
4. 均线周期顺序满足 `EMA7 < EMA25 < EMA90`。

### 爆发K线

合格金叉出现后的默认 3 个周期内，当前 K 线必须满足：

1. 收盘价高于开盘价。
2. 实体涨幅不低于配置的最小涨幅。
3. 实体涨幅严格大于此前 10 根 K 线中的最大实体涨幅。
4. 实体涨幅达到近期最大实体涨幅的指定倍数。

信号只使用已经完成的 K 线，不使用未收盘 K 线。爆发K线确认后提交入场意图，回测采用下一根 K 线开盘成交模型；实盘成交价格受行情、网络、订单类型和滑点影响。

## 仓位计算

策略按照初始风险距离计算目标名义仓位：

```text
单笔风险金额 = 当前账户权益 × 单笔风险比例
风险距离 = 信号收盘价 − 计划初始止损价
目标数量 = 单笔风险金额 ÷ 风险距离
目标名义金额 = 目标数量 × 信号收盘价
```

默认配置：

- 单笔风险：账户权益的 `0.5%`
- 单品种最大名义仓位：账户权益的 `30%`
- 最大同时持仓：3 个
- 当日权益回撤达到 `2%` 后停止新开仓
- 策略允许的最高杠杆：3 倍

最高杠杆只是部署许可，不会自动要求使用 3 倍。实际杠杆由部署配置决定。

## 初始止损

计划止损分别计算：

```text
结构止损 = 金叉至爆发K线之间的最低价 − 0.2 × ATR
波动止损 = 预计入场价 − 2.5 × ATR
初始止损 = 两者中的更低值
```

入场订单同时附带一个基于信号价格换算的百分比紧急止损。该保护由 QD 的实时保护引擎监控，可以在两根 1 小时 K 线之间触发。

由于实际成交价可能与信号收盘价不同，百分比紧急止损与图表上的绝对结构止损可能存在少量偏差。策略持仓确认后，会使用实际持仓均价重新计算内部初始风险线。

## 持仓退出

### 初始止损

在ATR追踪启动前，如果当前 K 线最低价触及初始止损，执行初始止损退出。

### 形态失败

入场后的前 3 根 K 线内，如果收盘价跌破爆发K线低点，执行形态失败退出。

### 趋势退出

满足任意条件时退出：

1. 收盘价跌破此前 10 根 K 线最低价。
2. EMA25 向下跌破 EMA90。

### 动能停滞

入场 8 根 K 线后，如果最大有利波动仍未达到 `0.5R`，并且 EMA7 已低于 EMA25，执行动能停滞退出。

### ATR追踪止盈

当持仓最高价达到 `2R` 后启动ATR追踪：

```text
ATR追踪价 = 持仓最高价 − 3.5 × ATR
```

追踪价不能低于初始止损，只能向盈利方向收紧，不能下降。当前版本在每根 1 小时 K 线收盘后更新ATR追踪价；实时保护引擎负责额外的百分比紧急止损。

## 退出优先级

同一根 K 线出现多个退出条件时，按以下顺序处理：

1. 初始止损或ATR追踪止盈
2. 形态失败
3. 趋势退出
4. 动能停滞

存在退出订单时不会重复提交退出。

## 状态与异常保护

策略开启 `PERSIST_RUNTIME_STATE`，保存每个品种的入场等待、持仓风险、最高价、ATR追踪价、订单引用和最后处理状态。

策略还会：

- 使用稳定的 `client_order_id` 防止重复订单。
- 在订单被拒绝、失败、取消或过期后释放入场状态。
- 以实际策略持仓作为持仓确认依据。
- 达到最大持仓数或当日回撤限制后停止新开仓。
- 保留已有持仓的退出处理。

## 使用顺序

1. 在 Strategy IDE 中创建 Strategy API V2 策略。
2. 粘贴 `docs/examples/strategy_v2_ema_cross_burst_long_swap_1h.py` 的完整内容。
3. 校验策略并确认清单显示：Crypto、swap、1h、long_only。
4. 先进行包含手续费和滑点的历史回测。
5. 查看成交明细、订单账本、最大回撤和各品种持仓。
6. 创建 `signal` 部署观察入场信号频率。
7. 实盘前确认交易账户、双向/单向持仓模式、保证金模式、杠杆、最小下单金额和通知渠道。
8. 使用小额资金创建 `live` 部署，并手动启动。

## 风险边界

回测结果不代表未来收益。永续合约还存在资金费率、强平、交易所限制、网络中断、滑点和订单状态不确定等风险。Strategy API V2 当前回测不会自动模拟永续合约资金费率，因此评估结果时需要单独估算资金费率影响。
