# MCP 通知需求与确认范围

## 目标

增加通用 `send_notification` 工具，让 ChatGPT 将重要分析发送到 QuantDinger
已有且启用的 Webhook。复用现有通知发送器，不新增 AI 服务、交易操作或调度任务。

## 用户确认的简化方案（2026-10-13）

- 复用 Agent `N` 权限，不新增 `NS`。发送权限同时包含已有告警任务管理能力。
- OAuth 复用其他通知写工具的 `quantdinger.write`，不新增通知专用权限。
- 复用现有 Agent 幂等及限流，取消通知专用表、迁移和跨 Token 去重设计。
- MCP 必填 `idempotency_key`，转换为 HTTP `Idempotency-Key`；重复请求重放原结果。
- 发送失败、超时和重试复用原 Webhook 发送器，不增加补发系统。
- 保留标题、正文、级别校验，以及飞书等文本渠道的标题和级别修复。
- 功能代码集中在独立通知模块，共享文件仅保留注册和必要安全脱敏接入点。
- 文本格式复用已有 `display.plain`，避免修改原发送器的事件识别逻辑。
- 调用者不得提供任意目标地址、Token 或请求头；通知内容及凭据不得写入审计摘要。

## 交付与验收边界

补充测试及中英文使用文档。模拟网络推送，不发送真实通知。
不合并、不部署、不交易、不更改已有 NEAR/USDT 监控。
后续单独验证线上手改 OAuth 文件一致性、交互 ChatGPT 调用，以及定时任务
是否支持无人值守调用 MCP；不得假定这些能力已验收。
