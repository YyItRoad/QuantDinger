# 行情分析模块第三步：可替换模板的单次分析

## 本步目标

把执行流程固定下来，把计算内容留在模板里。复用现有能力，不在分析服务里固化当前行情形态的判定算法。

流程：任务 → 已收盘行情 → 按清单计算指标 → 隔离执行计算脚本 → 将事实交给 AI → 校验输出 → 保存结果。

本步提供内部 AnalysisService.run_once(user_id, task_id, recipe=None)，未接周期调度、公开执行接口或前端执行按钮。任务不会因服务启动或新增而自动运行。

## 改动范围及复用

| 能力 | 本步实现 |
| --- | --- |
| 行情 | 复用 CryptoDataSource.for_exchange 的交易所绑定只读来源，核验现货或合约、原生品种标识和周期 |
| 指标 | 复用策略调用的 compute_talib_indicator，按模板名称及参数计算；不计算未声明的指标 |
| 自定义计算 | 复用 safe_exec_isolated，独立进程、干净环境、静态检查、执行超时及既有资源限制 |
| AI | 复用 LLMService 和当前默认模型，关闭模型及供应商自动回退，不调用旧一键分析的交易建议流程 |
| 存储 | 复用第二步两表及 save_result，仅增加按用户取任务和按收盘时间查结果的两个方法 |

没有修改策略、行情、指标库、模型服务、隔离执行器的原代码，也没有引入额外依赖。前端、接口及数据库迁移保持不变。

## 模板如何替换

模板由以下内容构成：

- name、version：模板名称和版本。
- bars：输入的已收盘行情数量。
- indicators：别名对应指标名称和参数，仅执行清单内指标。
- params：自定义脚本参数。
- code：处理行情和指标的脚本。
- prompt：让 AI 根据计算结果作判断的中文提示词。

默认入口是 app/market_state/recipe.py，脚本为 templates/basic.py，提示词为 templates/基础行情观察.md。第一版由开发者维护这些独立文件，不增加模板管理页面，不从用户请求接收可执行代码，也不让模型每次生成计算脚本。

脚本输入 df、indicators 和 params。df 是已收盘行情；indicators 中的值保留原指标库返回的 Series 或多输出 DataFrame。脚本输出非空 JSON 对象 output，供 AI 使用。可改指标清单，也可完全不用指标库而只执行脚本。计算失败明确报错，不以原行情副本伪装成成功结果。

默认模板读取 180 根已收盘行情，按清单计算 SMA7/25/90、ATR14，整理最近 120 根价格、最近 6 个指标值及相对位置。可以替换为 RSI、MACD 或其他计算，不修改主服务。

这是基础观察模板，不是旧《行情状态定义整理》完整规则的实现。Swing 确认、五维阈值和阶段候选算法没有写入主服务。后续细化分析方法时改模板，不需要重写执行链路。

## 校验与追溯

- 收盘前剔除未完成行情；检查时间单位、周期对齐、重复、缺口、行情数量、最新收盘时间及 OHLC 有效性。
- 模板输入最多 1000 根、32 项指标；脚本执行限制 20 秒；输出限制 256 KB；模型输出限制 64 KB。
- 输出验证五维及阶段字典、置信度、理由、证据格式、事实引用存在性；摘要由最终字段生成。
- 本步不宣称能自动核验自由文本中的每个数值或所有语义矛盾，也不以程序候选覆盖 AI 结论；这类深度校验应随分析模板继续完善。
- 结果保存原始输入、计算事实、脚本及提示词快照、参数、版本和内容摘要。模型信息记录请求的供应商和模型名，不冒充供应商返回的实际模型标识。
- 不读取历史分析作为本次 AI 的输入；同一任务同一收盘时间已有结果时直接返回，不重新计算或调用模型。
- 计算前及模型调用前检查任务；保存时继续使用事务中的 revision 校验，阻止已停止、删除或修改任务的旧结果落库。

## 当前边界

1. 单次执行首版仅支持 Crypto 的原生 1h、4h、1d，严格绑定交易所及 spot/swap。不支持的品种、非原生周期和行情不足均报错，不改用其他市场或交易所。其他市场仍可管理任务，但执行需先接交易日历；代币化股票等特殊来源待单独验证。
2. 数据源绑定来源核验依赖其既有内部辅助方法，本步未为此重构原数据源；未来若原接口变化，需要同步回归此适配层。
3. 使用 TA-Lib 的现有算法；不可用时明确失败，不静默切换另一种指标算法。
4. 目前只有串行重复调用的模型费用去重。数据库唯一键可防重复结果，但并发调用仍可能重复请求模型；跨进程执行租约留到调度阶段。
5. 模型调用已发出后停止任务，不保证取消在途调用或费用，但会拒绝旧结果落库。
6. 没有自动重试、失败记录表、通知、订单、持仓访问或交易策略执行。

## 验收方式

测试使用合成行情和模型替身；实际执行项目指标库及隔离脚本，并在独立临时 PostgreSQL 中完成结果落库、查询和幂等验证。不调用真实行情、付费模型，不运行生产迁移或部署。

最终回归结果：111 项通过。包含单次分析、真实 PostgreSQL、原分析接口、TA-Lib 适配、隔离脚本安全、数据库初始化和事务、持仓交易历史测试。另通过 git diff --check。本步未修改前端，未重复执行浏览器验收，也未做真实供应商联调。

重点审查：

1. app/market_state/recipe.py 与 templates：确认计算方法可替换。
2. app/market_state/service.py：确认只有编排、数据及格式校验，没有形态判断引擎。
3. app/market_state/repository.py：仅新增两个只读查询。
4. tests/test_market_state_service.py 与 test_market_state_postgres.py：替换指标和脚本、真实隔离执行、错误中止、来源绑定、用户隔离、状态变更、幂等和真实存储。

临时预览服务与测试页面继续排除在正式提交之外。本步不推送、不合并主分支、不自动部署。用户审查通过后再接周期调度。
