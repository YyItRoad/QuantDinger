# 行情分析模块第一版开发设计

状态：开发设计讨论稿，原型已确认；本文不代表已实施或已部署。

## 1. 已确认范围

- 新增顶级菜单「分析」，与「持仓」「AI助手」并列。
- 默认展示「分析记录」，第二页为「分析任务」。
- 两页均使用币种下拉、周期筛选和分页。
- 记录按分析完成时间倒序展示；不展示排序说明。
- 任务列表只展示品种、周期、操作；支持停止、启动、删除。
- 新增任务选择市场、品种及周期；数字货币还选择交易所和现货或合约。模型使用系统默认配置。
- 每个任务对应一个具体品种、一个周期，持续分析该周期新收盘的K线。
- 记录详情展示五维、Phase、Confidence、Summary和依据；去掉技术信息区及重复历史列表。
- 第一版不接通知、四种交易策略、下单或持仓操作。

## 2. 复用与独立性

本次核对范围为当前后端worktree以及主项目旁的QuantDinger-Vue源码，未核对正在运行的数据库和部署配置。

| 能力 | 复用对象 | 新模块的责任 |
| --- | --- | --- |
| 登录、用户隔离 | login_required、g.user_id | 每条任务及结果查询都限制所属用户 |
| 数据库 | get_db_connection、现有迁移执行机制 | 新增本模块两张表，不改原分析表 |
| 行情 | KlineService、DataSourceFactory及既有交易所适配 | 确认真实来源、标准化时间、筛出已收盘且连续的K线 |
| 模型 | LLMService和系统模型配置 | 专用提示词、状态字典、解析与严格校验 |
| 后台执行 | Celery、Beat、现有ai队列 | 模块自己的扫描和执行函数 |
| UI | Ant Design Vue、布局、请求封装、菜单权限惯例 | 独立页面、接口文件和局部组件 |
| 品种选择 | 现有market API、marketContext常量、搜索逻辑 | 小范围提取可共享的选择片段，不复制整页 |

不调用FastAnalysisService.analyze作为状态分析入口：它包含新闻、综合共识、交易建议和交易报告校准，不符合单周期独立判断。

不直接调用portfolio_monitor的完整运行流程：它包含持仓、计费和通知业务。复用公共服务和执行基础设施，而非这些业务入口。

Strategy API V2保留为后续使用分析结果的入口；第一版无需创建策略源码或策略部署实例。

## 3. 两张表的职责

### 持续分析任务：qd_market_state_tasks

新增这张小表是因为任务即使尚未产生结果，也必须能够被查询、停止和删除。现有qd_analysis_tasks在Fast Analysis中主要充当统计存档，不能直接视为通用调度主表。

业务字段：id、user_id、market、symbol、exchange_id、market_type、instrument_id、timeframe、enabled、created_at、updated_at、deleted_at。

最少运行字段：revision、next_run_at、last_bar_close_at、lease_token、lease_expires_at、retry_count、last_error。

- 运行字段不因此增加页面列；用于防止重复执行、恢复中断和定位失败。
- 同一用户、完整品种口径、周期只允许一项未删除任务，已停止任务也占用该唯一位置；可以重新启动。
- 删除采用软删除：关闭任务并设置deleted_at，页面不再显示，既有结果保留。
- 停止、启动、删除均递增revision，用于拦截操作前已排队或正在执行的旧任务。

### 分析结果：qd_market_state_results

沿用已讨论的结果字段，并新增task_id关联本模块任务。

- id、user_id、task_id。
- market、symbol、exchange_id、market_type、instrument_id、timeframe：本次实际分析对象快照。
- bar_close_at、created_at：最后参与分析的K线收盘时间及结果完成保存时间。
- trend、structure、ma_state、position、momentum、phase、confidence、summary。
- details：计算事实、收盘价、关键位、证据、实际数据源、实际模型及规则/提示词版本。

保留对象快照便于历史独立查询，不依赖品种目录、自选、币种池或策略记录。数据源降级不能静默改变交易所/品种口径。

关系约束：任务和结果均属于登录用户；结果task_id关联任务且禁止级联删除结果；写入时从任务取得用户归属，不信任客户端传入user_id。

唯一约束(task_id, bar_close_at)：第一版同一任务对同一根已收盘K线只保留一个成功结果。不加入强制重跑、结果修订功能。

记录分页索引优先(user_id, created_at DESC, id DESC)，再按实际筛选增加(user_id, symbol, timeframe, created_at DESC, id DESC)。任务唯一索引覆盖完整品种身份并排除软删除项，身份字段统一非空标准值。

失败记录在任务last_error及现有日志中体现，不把失败伪装为正常行情状态写进结果表。第一版不另建运行日志表。

## 4. 执行流程

建议首次启动等待下一根周期K线收盘，沿用确认原型；停止再启动也从后续新收盘K线继续，不批量补算停用期间历史。

1. 创建任务并计算下一次应检查时间，保存后立即返回。
2. Beat定期扫描到期任务，短事务领取并设置有期限的执行租约，再投递ai队列。
3. Worker核对任务仍启用、未删除、revision和租约仍有效。
4. 获取对应品种和周期的K线，验证来源、完整性以及最后收盘时间；没有新的完整K线则稍后再检查，不调用模型。
5. 从当前窗口计算已确认的客观事实，调用系统默认模型，校验五维、Phase、置信度与证据。
6. 短事务再次核对任务revision、启用状态和租约，再保存结果、推进last_bar_close_at及下一次检查时间。

耗时行情/模型请求期间不持有数据库事务锁。

停止或删除后，旧Worker不再提交结果。已经发送给模型供应商的请求可能无法撤销，不能承诺立即取消成本。并发保存与停止通过同一任务行锁排序：停止操作提交后，旧执行不能再写结果。

投递失败或Worker中断时租约到期允许重新领取；旧Worker不能释放新租约。任务领取、唯一结果约束及最终状态检查共同处理重复投递；不承诺外部AI调用严格只执行一次。

一次失败有限重试并记录错误。正常扫描不等于每分钟调用AI。应用重启后优先处理最近尚未分析的完整K线，不追补所有错过的历史周期。

周期边界取数据源/交易市场的实际收盘语义，不能把A股交易时段、休市和数字货币24小时交易统一当成固定秒数。数据尚未更新或休市时不产生重复分析；未验证的市场周期组合不应开放创建。

默认模型在运行时读取，结果保存实际模型标识。既有计费开启时沿用项目计费政策及公共计费服务，不能通过新增入口绕过收费；具体开关和worker队列部署需上线前核对。

## 5. 最小接口与页面

建议独立前缀/api/market-state：

| 接口 | 用途 |
| --- | --- |
| GET /records | 按完成时间及id倒序分页；支持币种、周期筛选 |
| GET /records/:id | 读取单条结果详情 |
| GET /tasks | 分页获取未删除任务，按创建时间及id倒序 |
| POST /tasks | 创建并启用持续分析 |
| PATCH /tasks/:id | 启动或停止，不提供复杂配置编辑 |
| DELETE /tasks/:id | 停止并软删除任务，保留记录 |

币种下拉来自对应列表的全部可见数据，不只取当前一页；可由列表响应附带独立去重选项，空列表仍显示「全部币种」。品种行保留交易所和类型，避免同名记录混淆。

前端使用a-tabs、a-table及其分页、a-select、a-modal或a-drawer。新增表单以小范围共享选择组件复用现有行情搜索，不复用“添加自选”的写入动作。

运行状态、下次分析和最近完成不单独成列。任务enabled只决定按钮显示「停止」还是「启动」。失败可以用该行简短异常提示呈现，避免用户以为正常运行而一直没有结果。

进入页面、切换页签及操作后刷新；若需要驻留更新，只做本页轻量轮询，离开或停用页面时清理，不引入WebSocket。

## 6. 代码落点与修改边界

新增后端目录app/market_state/，初期包含routes.py、service.py、repository.py、analyzer.py、prompt.py、tasks.py和__init__.py；不建设通用规则引擎或通用任务平台。

新增独立SQL迁移，沿用app/utils/db.py的迁移组件注册方式。

已有后端文件只在app/openapi/register.py添加路由注册、app/celery_app.py添加任务导入/路由/扫描调度、数据库迁移注册处添加一个组件。若底层数据函数需要小修，必须有具体口径问题和回归证据，不能顺便重构。

前端新增src/views/market-state/及src/api/market-state.js；已有代码只增加顶级路由和菜单文案，必要时小范围提取共享品种选择组件。共享组件接回旧页面时验证旧搜索与添加自选流程。

后端当前worktree和主项目旁的前端不是同一checkout。实施前确认两个仓库的分支和未提交修改，再在对应隔离工作区改动。

## 7. 开发顺序与验收

1. 两表、查询接口、任务启停删除：先验证结果与任务归属、分页、唯一约束和删除保留历史。
2. 单次真实分析函数：验证已收盘K线、客观规则、AI校验与保存，不立即打开持续调用。
3. 接入周期调度：验证重复投递、租约过期、停止/删除期间返回结果、失败重试及重启恢复。
4. 接入确认原型：验证下拉覆盖所有页、组合筛选回第一页、任务启停按钮、结果详情和空/失败反馈。
5. 回归现有AI助手品种选择、原分析入口、持仓页面及相关数据接口；完成前端构建与后端针对性测试。

持续调度是第一版交付范围，以上只是开发顺序。实现完成不自动授权生产迁移、部署、启动真实持续分析或产生AI调用费用；这些仍按用户具体授权执行。
