# 行情分析模块第二步：正式存储

## 已完成

- 独立 PostgreSQL 两表：qd_market_state_tasks、qd_market_state_results。
- 沿用原数据库事务连接及启动迁移组件，在基础表之后执行独立迁移文件。
- 默认使用数据库；仅显式开启演示开关时使用 SQLite 假数据，不将假数据迁入正式表。
- 接口路径、分页结构、筛选及详情结构保持不变；响应 mode 区分 database、demo 和 unavailable。
- 数据库模式也可新增、启停和删除任务；页面明确提示执行功能尚未接入，不声称任务已在运行。
- 用户隔离、同品种周期唯一、任务软删除、结果独立快照、分页及跨页币种下拉。
- 内部 save_result 接口为下一步预留：从任务取得品种快照，检查归属、启用状态和 revision，按任务及收盘时间幂等保存，不覆盖旧结果。

## 表关系

任务只依赖已有用户记录，不要求品种目录、自选、持仓、策略或交易所账户表已有数据。

结果依赖本模块任务，复合外键保证任务和结果同属一个用户。删除任务走软删除，不级联删除结果；用户注销时沿用项目用户数据清理规则。

任务唯一键为用户、市场、品种、交易所、现货或合约、周期，排除已软删除任务。instrument_id 是来源快照而非另一个重复创建入口。

时间使用 TIMESTAMPTZ，接口输出带 UTC 时区的 ISO 时间。Phase 和置信度设基础约束；五维业务字典、模型输出校验将在单次真实分析阶段完善。

目前只增加 revision 防止旧结果落库；调度租约、下次执行时间及重试字段留到调度阶段，避免提前引入未使用的执行逻辑。
