# 持仓管理强平记录修复

## 修复范围

在现有持仓同步周期中核对 Binance USDT 合约的完整强平，包括已停止但仍有本地持仓的管理实例。不新增表，不发出交易订单，不更改止损策略。

交易所对应方向仓位为零、登记之后发生的强平订单数量等于本地剩余仓位、订单真实成交完整且唯一归属于该策略时，复用成交入账函数扣减本地仓位，保存真实价格、数量、时间、已实现盈亏和手续费，随后复用停止与历史归档流程。平仓原因显示为“交易所强平”。

重复查询通过既有策略成交锁及交易所订单、成交编号检查防止重复入账。入账和本地持仓更新在同一数据库事务中完成。

## 外部平仓与历史空字段补齐

普通外部平仓复用已有 Binance 成交查询和订单查询。只有仓位减少量等于未入账的完整平仓成交总量、同侧仓位唯一归属该策略、订单未绑定系统请求时才补记；部分平仓保留剩余仓位，全部平仓复用原有停止和归档。单向模式还要求订单为只减仓。登记之后出现新的开仓、接口分页不完整或订单部分入账时不自动处理。普通外部订单不能证明由用户手动操作，统一标记“交易所外部平仓”。

历史已有记录也会补齐空的交易所订单编号、类型、状态、委托数量、客户端编号和创建时间，不修改成交价格、数量、盈亏或系统订单归属。文字退出原因仅从同用户、策略、账户、币种、方向、数量一致，且发生在退出后一天内的唯一失败关闭请求中补取；已有备注不覆盖。没有系统订单意图、信号和发送记录的字段保持为空。

## 保留待核对的情况

- 接口失败、仓位响应为空或成交数据不完整。
- 无法满足上述归属和数量核对的外部平仓、部分强平、多张强平订单才能覆盖剩余仓位。
- 同一账号、币种、方向有多个策略持仓，或已有部分成交入账。

以上情况不清理本地持仓、不估算平仓价格。后续同步会再次核对，但交易所历史查询仍受其保留范围限制。

## 部署与验证

本次无需数据库迁移。更新后端及交易工作进程代码后，既有持仓同步周期会执行核对；不需要再次点击平仓。成交函数原有生命周期检查负责自动停止，现有历史定时任务负责归档，强平模块不重复调用这两个流程。历史列表应出现“交易所强平”，并核对交易所实际成交时间、数量、价格和盈亏。

本地回归覆盖完整强平、成交不完整、接口异常、重复成交、归属冲突以及已停止实例的扫描。线上数据未修改，部署后仍需核对 PROM 实际强平记录。
