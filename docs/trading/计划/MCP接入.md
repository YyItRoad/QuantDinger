# 计划管理：网页与 MCP

提供计划管理、已有交易关联和基础复盘，不提交订单、不启动或停止策略、不接管持仓、不修改保护价格。2026-10-25 已随计划 v1 发布到生产；发布证据和验证边界见[部署与验收](部署与验收.md)。本页是[计划模块](README.md)的 MCP 专项说明。

网页入口为“计划”（`/trade-plans`）。正式数据统一保存在 QuantDinger PostgreSQL。无账户也能建立仅含标题的草稿；进入观察要求文字决策卡完整，数值风险不足时明确显示缺口。

## 工具与权限

| 工具 | Agent 权限 | 用途 |
| --- | --- | --- |
| `list_trade_plans`、`get_trade_plan` | R | 列表、详情、当前检查及信号状态 |
| `list_trade_plan_versions`、`get_trade_plan_version` | R | 不可覆盖的历史版本 |
| `list_trade_plan_events` | R | 决策日志；完整性与基础风险随详情返回 |
| `get_trade_plan_request` | R | 查询超时写请求的实际保存结果 |
| `create_trade_plan` | W | 新建草稿 |
| `revise_trade_plan` | W | 追加修订，必须说明原因 |
| `set_trade_plan_state` | W | 观察、撤回、取消、结束 |
| `copy_trade_plan` | W | 复制成独立草稿，保留父计划关系 |
| `record_trade_plan_decision` | W | 记录信号判断及观察时间；AI 建议不能冒充人工确认 |
| `list_trade_plan_accounts` | R | 查询当前用户的脱敏账户身份，含独立历史中的已删除账户身份 |
| `list_trade_plan_sources` | R | 按采用版本、账户和来源类型分页预览已有事实；不查询交易所 |
| `create_trade_plan_attempt` | W | 固定采用版本、参考风险、账户和交易环境 |
| `link_trade_plan_record` | W | 引用服务器核验的已有事实，归属可待确认 |
| `revoke_trade_plan_link` | W | 撤销错误关联并保留旧快照和原因 |
| `refresh_trade_plan_link` | W | 追加新事实快照，或核验后确认归属；不覆盖旧快照 |
| `save_trade_plan_review` | W | 追加行情判断、策略规则、实际执行和改进，保存当时依据与事实 |

OAuth 读取对应 `quantdinger.read`，写入对应 `quantdinger.write`，上游 Agent R/W 仍独立检查；不需要 T、N 或 B。用户归属、标的范围、限流和审计沿用 Gateway。

## 保存与重试

每次写操作必须提供调用方生成的 `idempotency_key`。MCP 将它同时传入 `Idempotency-Key` 和 `request_id`；网页也使用 request_id。修改已有计划另需 `expected_revision`，从最新详情取得。重复请求必须复用原键和原内容；更改内容或解决版本冲突后使用新的键。

写入只返回计划ID、版本ID/号、修订号及请求ID；再调用详情读取内容。数量与风险预算二选一，不能同时提交有效值。

同键同参回放原结果，同键异参或旧 revision 返回 409。请求超时先查询 `get_trade_plan_request`，不确定时重试原键；不要直接另建计划。业务变更与回放结果在同一个 PostgreSQL 事务中保存。

计划写入口使用领域事务回放，重试时重新检查最新权限；仍由 Gateway 检查认证、scope、请求键长度、限流及审计。新增关联/复盘动作的响应版本指向其采用的计划版本，可能早于当前计划版本；计划最新状态继续从详情读取。

实际数字货币快捷开仓现在使用原开仓原因语义记录市场状态和想法，不要求先建立计划。网页传 `entry_reason`；Agent/MCP 实盘现货买入和合约开仓同样必填（最多 500 字），原因先写入已有快捷交易记录再提交订单，历史返回原文；现货卖出、平仓及撤单不受必填限制。详见[使用说明](使用说明.md)。

## 网页交易关联与复盘

打开计划详情的“交易与复盘”页签：新增一次交易记录 → 选择采用版本/账户/环境 → 关联已有记录并核对预览 → 保存复盘。日常仅记研究时可以继续使用草稿，不要求新增交易记录。

现有持仓管理的交易历史详情、数字货币快捷交易记录提供“查看计划/复盘”跳转。已有唯一活动关联时打开原计划及对应交易记录；没有明确关联时显示同品种研究，由用户选择或新建，不自动关联。新建仅带入品种和方向等身份信息；从成交或历史记录新建会标记历史补录，不自动生成想法或证据，也不改变现有开仓流程。

读取 API 和 MCP 的 `list_trade_plans` 支持成对传入 `source_kind` / `source_id` 查找活动关联，成交与独立历史按同一成交身份查找；已撤销的关联不命中。`list_trade_plan_sources` 支持可选 `source_id` 精确预览，仍按服务器核验的账户、采用版本、品种及租户过滤后分页。

来源类型为 `strategy`（持仓管理策略）、`order`（策略订单）、`quick_order`（快捷订单）、`trade`（成交）、`history`（独立持仓管理历史）。同一成交及其归档/执行事件/交易所成交身份只允许一个活动归属。策略与订单引用不会自动展开为全部成交，也不代表交易已经发生；需明确关联实际成交。无法确定身份或归属时保留待确认，不分摊数量。

刷新通过撤销旧关联快照、追加新快照完成；来源已删除时保留原事实并注明当前不可读取。撤销不删除历史；复盘仍引用保存时的快照。已持有、部分退出或事实/归属未知的记录会阻止结束研究；取消计划不影响实际仓位。

复盘 `assessment` 包含 `market_judgment`、`strategy_rules`、`execution` 三项，每项为 `value` 和 `reason`，另有 `improvement`。枚举见机器契约，资料不足选择 `not_evaluable`。每次保存必须提供 `change_reason`，内容追加为新复盘版本；阶段复盘不会被后来的闭合事实改写。

## 数据与风险口径

计划完整性、信号判断和实际交易状态分开显示。新版信号恢复未评估；历史版本和旧判断仍可查询。取消、到期、结束后通过复制继续研究，不能重新启用原计划。

计划首次保存具体标的后，市场、品种代码、交易所、产品类型、原生标识和结算币不能在修订中更换或清空；更换标的请新建计划。仅有标题、尚未选择标的的草稿可以首次补齐标的。网页禁用相应选择框，Web/Agent/MCP 共用的服务端校验同样拒绝绕过请求，返回 `422 plan_instrument_immutable`。引用的分析在已知市场、品种、交易所、产品类型及原生标识上必须与计划相符，否则返回 `422 research_instrument_mismatch`。分析/决策周期、想法、条件和风险参数仍可正常修订，旧版本与已采用风险不变。

基础风险首批支持数字货币现货做多与线性合约多空，数量使用基础资产单位。计划 1R 为参考入场价与初始止损价之间的价格风险，不含费用与滑点。新增交易记录时固定采用版本及检查结果，后续计划修订不改变该分母；改变参考风险需先修订计划。缺少输入、方向错误、币种冲突和不支持的产品均返回明确状态。

可信事前依据还需核对实际入场时间：优先使用同用户、账户和品种的执行事件发生时间，记录入库时间、策略创建时间不冒充开仓时间。晚录、终态后新增、已过期依据或时间无法核验时，不输出可信净 R。只有已关联成交闭合、身份及费用完整、币种一致、事前风险可核验时，才评估净收益/净 R。当前已实现逐笔现货买卖的可核验计算；合约单位与资金费不能完整归属时明确不可评估，仍可做三维文字复盘。订单汇总不与逐笔成交重复累计，原账本收益不作为已核验净收益直接相加。

历史补录应标识，不应为填满表单而编造证据。市场分析引用保存结果 ID、截止时间和服务器读取的当时摘要。

## 安装与运行边界

迁移依次为 `backend_api_python/migrations/20261023_trade_plan_management.sql` 和 `20261024_trade_plan_records.sql`，完整初始化同步包含这两阶段结构。按既有迁移流程先更新结构，再使用相应后端、前端与 MCP 包。不能把源码工具新增视为线上工具已可用。

`TRADE_PLAN_MANAGEMENT_ENABLED=false` 可关闭计划 API；到期按读写时服务器时间判断，无专门后台任务；不会停止或改变现有交易。生产已应用两阶段迁移；具体发布版本见部署与验收。其他环境仍须按其实际结构和发布流程核验，不能把生产验收推及未更新环境。
