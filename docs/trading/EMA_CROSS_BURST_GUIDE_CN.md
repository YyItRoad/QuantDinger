# EMA 金叉爆发指标与策略指南

## 目标形态

这套规则用于识别以下多头形态：

1. EMA25 从下向上突破 EMA90；
2. 金叉确认时 EMA7 同时位于 EMA25 和 EMA90 上方；
3. 金叉当根或之后指定数量的 K 线内，出现一根明显强于此前 10 根 K 线的阳线实体；
4. 用 ATR、结构低点、趋势破坏和动能停滞管理风险与退出。

空头版本采用镜像规则：EMA25 向下跌破 EMA90、EMA7 位于两条均线下方，并等待明显强于
近期下跌实体的大阴线。

## 三种实现的职责

| 实现 | 用途 | 是否下单 | 是否统计回测收益 |
| --- | --- | --- | --- |
| QuantDinger 图表指标 | 在真实 K 线上选择一笔模拟入场，查看止损、追踪启动和退出位置 | 否 | 否 |
| Strategy API V2 多头/空头策略 | 按同一形态进行开仓、持仓管理、回测、模拟盘和实盘 | 是 | 是 |
| AiCoin 指标 | 在 AiCoin K 线上显示同类标记并创建预警 | 否 | 否 |

指标和策略共享主要形态与持仓管理思想，但用途不同。指标中的“模拟入场”和“模拟退出”是
为了观察规则效果，不代表真实成交；策略的成交还受下一根 K 线、手续费、滑点、订单状态和
交易所规则影响。

## 信号定义

### 合格金叉

默认 EMA 周期必须满足：

```text
7 < 25 < 90
```

多头合格金叉同时要求：

```text
本根 EMA25 > EMA90
上一根 EMA25 <= EMA90
本根 EMA7 > EMA25
本根 EMA7 > EMA90
```

慢线至少积累完整周期后才允许确认信号，减少起始数据不足造成的假交叉。

### 爆发 K 线

多头实体涨幅定义为：

```text
实体涨幅 = close / open - 1
```

当前 K 线必须：

- 收盘高于开盘；
- 达到 `min_body_rise_pct` 最低涨幅；
- 严格大于此前 `comparison_bars` 根 K 线的最大实体涨幅乘以
  `burst_multiplier`；
- 位于合格金叉当根至其后 `nearby_bars` 根 K 线的有效窗口内。

默认参数下相当于：金叉当根或之后 3 根 K 线内，当前阳线实体严格大于此前 10 根 K 线的
最大阳线实体。

“Qualified Cross”对应“合格金叉”，“EMA Burst”对应“满足金叉邻近窗口的爆发 K 线”。

## 共用持仓管理规则

### 虚拟或计划入场

爆发 K 线只有收盘后才能确认，因此图表指标和回测策略都以信号后的下一根 K 线开盘作为
入场参考。实盘最终价格以交易所成交回报为准。

### 初始止损

多头分别计算：

```text
结构止损 = 金叉至爆发 K 线的最低价 - structure_buffer_atr × ATR
波动止损 = 入场参考价 - initial_atr_mult × ATR
初始止损 = min(结构止损, 波动止损)
R = 入场参考价 - 初始止损
```

空头对称计算结构高点和入场价上方止损。

### 形态失败

入场后的前 `failure_bars` 根 K 线内：

- 多头收盘跌破爆发 K 线低点；
- 空头收盘突破爆发 K 线高点；

则退出。

### 动能停滞

持仓达到 `stagnation_bars` 后，如果最大有利波动仍未达到 `stagnation_min_r × R`，并且
EMA7 已向不利方向越过 EMA25，则退出。

### 趋势退出

多头满足任一条件退出：

- 收盘跌破此前 `trend_exit_bars` 根 K 线低点；
- EMA25 向下跌破 EMA90。

空头使用相反条件。

### ATR 追踪

达到 `trail_activation_r × R` 后启动 ATR 追踪：

```text
多头追踪价 = 持仓最高价 - trail_atr_mult × ATR
空头追踪价 = 持仓最低价 + trail_atr_mult × ATR
```

追踪线只能向盈利方向收紧，不能重新放宽。

## 默认参数

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| `lead_ema_period` | 7 | 领先 EMA |
| `cross_fast_period` | 25 | 交叉快线 |
| `cross_slow_period` | 90 | 交叉慢线 |
| `comparison_bars` | 10 | 爆发实体的历史比较窗口 |
| `nearby_bars` | 3 | 金叉/死叉后的有效窗口 |
| `burst_multiplier` | 1.0 | 当前实体相对历史最大实体的倍数 |
| `min_body_rise_pct` | 0.0 | 多头阳线最低实体涨幅 |
| `min_body_fall_pct` | 0.0 | 空头阴线最低实体跌幅 |
| `atr_period` | 14 | ATR 周期 |
| `initial_atr_mult` | 2.5 | 波动止损距离 |
| `structure_buffer_atr` | 0.2 | 结构点外 ATR 缓冲 |
| `failure_bars` | 3 | 形态失败期限 |
| `stagnation_bars` | 8 | 动能停滞检查周期 |
| `stagnation_min_r` | 0.5 | 停滞检查要求的最小有利波动 |
| `trail_activation_r` | 2.0 | ATR 追踪启动位置 |
| `trail_atr_mult` | 3.5 | ATR 追踪距离 |
| `trend_exit_bars` | 10 | 趋势通道周期 |

需要更严格的爆发条件时，可先测试：

```text
burst_multiplier = 1.2
min_body_rise_pct = 0.8
```

参数必须通过回测比较，不应仅凭单次走势调整。

## 在 QuantDinger 中查看指标

1. 打开指标 IDE，新建图表指标。
2. 粘贴 [`chart_indicator_ema_cross_burst.py`](../examples/chart_indicator_ema_cross_burst.py)。
3. 选择目标品种和 K 线周期。
4. 运行指标并添加到 K 线主图。
5. 查看三条 EMA、合格金叉、爆发 K 线、模拟入场、初始止损、2R 追踪启动、当前有效止损、ATR 追踪和退出标记。

默认 `manual_entry_time=auto`，指标按爆发信号后的下一根 K 线开盘模拟入场。`trade_offset=0`
显示最近一笔，改为 `1`、`2` 可以依次查看更早的模拟交易。

需要复盘自己的单笔机会时，把 `manual_entry_time` 改为目标 K 线的 ISO 时间，例如
`2026-08-31T08:00:00+08:00`。`manual_entry_price=0` 使用该根 K 线开盘价；填写正数则使用指定
价格。手动模式使用 `manual_structure_bars` 根 K 线的结构低点计算初始止损。

指标会在 `calculatedVars` 中返回模拟状态、入场价、初始止损、2R 追踪启动价、退出原因、
退出参考价和无杠杆模拟收益率。当前前端如果没有展示 `calculatedVars`，仍可通过主图线条和
退出标记判断；该字段已经为后续详情展示保留。

真实运行时，持仓策略使用交易所同步的实际开仓均价和数量。指标中的价格只是复盘参考，不能
代替真实订单回报。

## 如何确认真实订单已经结束

指标只能回答“按规则应该在哪根 K 线触发退出”，不能证明交易所已经平仓。真实订单结束至少
需要同时核对：

1. 退出订单状态已经是完全成交，而不是 `pending`、`processing`、`sent` 或部分成交；
2. 实盘运行页面中的策略持仓已经归零；
3. 交易记录中已经出现对应的平仓成交和实际成交价；
4. 币安账户对应合约方向的真实仓位数量也已经归零。

运行日志中的“退出信号”只表示源码提交了退出意图；“Order queued”只表示订单进入队列；
“Trade executed”表示 Worker 已处理到成交，但最终仍应以币安仓位和成交记录核对。网络异常、
部分成交和交易所原生止损触发时，页面状态可能短暂滞后。

如果需要及时知道结果，可以为退出信号和成交结果启用通知；通知用于提醒，交易所仓位归零
仍是确认实盘订单结束的最终依据。

## 在 QuantDinger 中回测策略

多头与空头示例：

- [`strategy_v2_ema_cross_burst_long_swap_1h.py`](../examples/strategy_v2_ema_cross_burst_long_swap_1h.py)
- [`strategy_v2_ema_cross_burst_short_swap_1h.py`](../examples/strategy_v2_ema_cross_burst_short_swap_1h.py)

建议步骤：

1. 在策略 IDE 新建 Strategy API V2 源码。
2. 粘贴多头或空头示例并校验清单。
3. 确认静态合约池、`swap`、`1h`、方向和最高杠杆符合预期。
4. 设置足够长的回测区间，并计入手续费和保守滑点。
5. 查看 K 线成交标记、成交明细、权益曲线、最大回撤和分品种结果。
6. 分别回测上涨、下跌和震荡阶段，不以单一市场阶段判断有效性。
7. 参数稳定后先使用信号或模拟方式观察，再考虑小额实盘。

示例源码顶部的 `CONTRACT_POOL` 是策略清单的一部分。修改品种后需要重新保存、校验、回测
和部署。示例会在空仓时主动寻找入场，所以它们属于完整交易策略，不是“只管理手工仓位”的
持仓管理源码。

## 与持仓管理结合

指标可以用统一的虚拟入场点观察退出规则，完整策略可以回测同一套入场和退出组合；但真实
手工仓位的开仓规则和开仓价格不固定，无法直接还原成统一历史回测。

用于持仓管理时，应建立专用源码：

1. 保留 ATR、结构止损、形态失败、趋势退出和动能停滞等持仓逻辑；
2. 删除金叉、爆发 K 线触发的主动开仓路径；
3. 启动后读取已经登记的真实仓位均价、数量和方向；
4. 空仓时不再开仓；
5. 仓位归零后由持仓管理生命周期自动停止实例。

详细接管流程见[持仓管理使用指南](POSITION_MANAGEMENT_GUIDE_CN.md)。

## 风险说明

- 指标标记不是订单成交证明。
- 回测结果不代表未来收益，短策略也不能因为规则对称就假设有效。
- 永续合约还存在资金费率、强平、最小下单量、精度、滑点和网络风险。
- Strategy API V2 回测结果与交易所真实撮合可能不同。
- 在把任何源码交给真实仓位前，先检查它是否存在开仓、加仓或反手路径。
