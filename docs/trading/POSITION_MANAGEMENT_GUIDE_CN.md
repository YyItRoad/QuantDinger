# 持仓管理使用指南

## 功能目标

持仓管理用于把已经存在于交易所账户中的整笔仓位交给一个标准 QuantDinger
实盘策略实例管理。仓位可以由用户手动开出，也可以来自其他工具；接管后仍复用项目
原有的策略源码、运行周期、参数、实盘运行页面、订单流程、持仓同步和停止流程。

这一功能没有建立另一套策略执行器，也没有把策略中心拆成“开仓策略”和“持仓策略”。
“持仓”只是使用目的，策略源码仍由用户在原策略中心维护。

## 当前业务流程

```text
选择交易凭证
  → 从交易所同步当前仓位
  → 选择一笔未被管理的整笔仓位
  → 复用“创建实盘策略”表单选择源码和参数
  → 后端再次读取交易所最新仓位
  → 创建独立的标准 live 策略实例
  → 将整笔仓位登记到该实例的策略持仓账本
  → 用户进入实盘运行页面并手动启动
  → 原 trading-worker 按源码周期运行并同步仓位
  → 仓位归零后管理实例自动停止
```

持仓管理页面只负责同步、识别归属和创建实例。实例创建成功后的启动、停止、日志、
订单和运行详情继续使用策略中心已有页面。

## 页面使用步骤

### 1. 准备交易凭证

先在交易凭证页面保存可读取账户和仓位的凭证。实盘平仓还需要相应交易权限。
当前页面会展示能够读取账户快照的凭证，接口可以同步到什么市场和仓位，页面就展示什么，
不会额外构造品种或方向限制。

### 2. 同步持仓

打开“持仓管理”，选择凭证后点击“同步持仓”。页面显示交易所最新返回的：

- 品种；
- 现货或永续合约；
- 多空方向；
- 持仓数量；
- 开仓均价；
- 最新价格；
- 杠杆倍数；
- 当前管理策略。

“同步持仓”同时查询交易所仓位和 QuantDinger 已登记的标准策略持仓，然后按凭证、
市场、规范化品种和方向合并展示。它不是刷新凭证列表，也不会创建或修改策略。

### 3. 创建管理策略

对未被管理的仓位点击“创建管理策略”。弹窗复用现有“创建实盘策略”表单，可以配置：

- 策略源码；
- 策略名称；
- 运行参数；
- 初始资金等原表单已有字段；
- 通知等原策略配置。

凭证、执行模式、仓位杠杆和目标仓位由持仓管理流程确定，不能被表单中的旧值覆盖：

- 执行模式固定为 `live`；
- 凭证固定为当前同步仓位使用的凭证；
- 杠杆取交易所最新仓位的杠杆，并同时写入策略参数 `leverage`；
- 接管数量、开仓价和最新价在提交时重新从交易所读取，不信任页面缓存。

创建成功后，页面中的仓位会显示管理策略名称。点击名称可进入原有实盘运行页面。

### 4. 启动和观察

新实例创建后默认是停止状态，不会自动运行。进入策略中心或实盘运行详情页，检查以下内容
后再手动启动：

- 源码订阅的品种与当前仓位一致；
- 源码运行周期符合预期；
- 多空方向与当前仓位一致；
- 参数、杠杆、止损和退出规则正确；
- 交易凭证和通知配置正确。

启动后由原 `trading-worker` 执行策略。运行日志、订单记录、策略持仓和停止操作都在原有
实盘运行页面查看。

## 创建时系统实际完成的事情

创建接口会执行以下校验和登记：

1. 在锁外读取一次交易所账户快照，避免网络请求占用数据库临界区。
2. 优先按交易所 `inst_id` 和方向匹配目标；无法精确匹配时再按规范化品种、方向和市场匹配。
3. 现货缺少最新价时读取 ticker，仍失败时回退到可用的接管价格。
4. 为同一凭证、市场、品种和方向申请短租约，阻止双击或并发请求重复接管。
5. 在租约内重新检查该仓位是否已登记到其他策略。
6. 使用标准策略创建服务建立独立实例。
7. 确认策略源码清单包含当前品种；动态品种池源码按原清单语义处理。
8. 将交易所当前整笔数量、均价、最新价、方向、市场、凭证和 `inst_id` 写入
   `qd_strategy_positions`。
9. 标记该实例为持仓管理实例，并启用“仓位清零后自动停止”。

如果创建实例后仓位登记失败，系统会尽力删除刚创建的空实例；若自动清理也失败，错误信息
会给出残留策略 ID，用户应在策略列表中检查并删除。

## 持仓策略源码要求

持仓管理信任用户选择的策略源码，不会在通用 Executor 中额外禁止开仓、加仓或反手。
因此，专用持仓源码应满足：

- 启动时通过 `get_position()` 读取已经登记的真实策略仓位；
- 有仓位时只计算止损、止盈、追踪退出和其他减仓/平仓规则；
- 没有仓位时保持空闲，不提交新的入场订单；
- 不加仓、不反手，不把退出条件写成反向开仓；
- 平仓使用目标仓位归零等原 Strategy API V2 退出语义；
- 使用源码声明的 `frequency` 作为监控周期；
- 如有运行状态，开启并正确恢复 `PERSIST_RUNTIME_STATE`；
- 对未完成、失败或取消的退出订单保留重试与状态恢复逻辑。

普通完整交易策略通常同时包含入场和退出逻辑。即使它的退出规则符合要求，也不应直接作为
持仓管理源码，除非已经明确关闭空仓入场路径；否则原仓位退出后可能再次产生新仓位。

## 运行周期与实时保护

策略监控周期来自源码中的订阅声明，例如：

```python
context.subscribe(
    frequency="1h",
    fields=["open", "high", "low", "close", "volume"],
)
```

`1h` 表示策略主体通常在一小时 K 线数据更新时重新计算。它不等于交易所原生止损：如果只在
K 线周期内计算退出，极端行情中可能来不及响应。需要周期内保护时，应使用项目已有的实时
保护能力或交易所原生保护单，并确认这些保护与策略退出不会重复提交。

## 仓位同步和自动停止

运行中的策略会按原流程将交易所仓位同步回 `qd_strategy_positions`：

- 数量和均价变化时，策略账本更新为交易所最新状态；
- 用户手动平仓、交易所止损/止盈触发、爆仓或其他客户端平仓后，交易所数量为零，策略持仓
  记录被删除；
- 持仓管理实例的最后一笔仓位消失后，系统写入停止状态并投递标准停止命令；
- 拥有运行租约的 Worker 执行正常清理并释放运行资源；
- 自动停止不会再次平仓，因为交易所仓位已经为零。

## 停止与释放管理

持仓管理不增加独立“释放绑定”体系。使用实盘运行页面已有停止动作：

- **仅暂停**：停止策略运行，但不要求平掉交易所仓位；仓位仍可能保留在交易所，
  之后需要重新同步并决定是否再次交给策略管理。
- **暂停并平仓**：请求停止策略，同时按原有策略停止流程提交平仓；执行前必须核对仓位和挂单。
- **仓位自行归零**：同步确认后，持仓管理实例会自动停止。

停止或删除策略前应先检查未成交订单。不要在交易所、其他机器人和 QuantDinger 中同时对
同一整笔仓位运行互相冲突的退出逻辑。

## 常见问题

### 同步后仍看不到仓位

依次检查：

1. 页面选择的是创建该仓位所用的交易凭证；
2. API Key 具有读取目标市场账户的权限；
3. 交易所返回的仓位数量不是零；
4. 代理在 Docker 容器网络中可用，而不只是宿主机浏览器可用；
5. 后端日志中是否存在交易所鉴权、地区限制、超时或市场类型错误。

### 提示“交易所中已找不到该仓位”

创建管理实例前系统会再次读取交易所。页面缓存中的仓位已经变化或归零时会拒绝创建，重新
同步即可。

### 提示“该仓位已经由策略管理”

同一凭证、市场、品种和方向已经登记在标准策略实例中。先点击现有策略名称检查，不要重复
接管。

### 提示“该仓位正在被接管”

另一个创建请求正在处理同一仓位。不要连续提交，等待后重新同步。

### 提示“策略源码没有订阅当前仓位品种”

所选源码的策略清单不包含该品种或市场。修改源码清单、重新校验保存，或选择匹配当前仓位的
源码。

### 现货没有开仓均价

部分现货钱包接口不提供成本价。当前实现会尽量读取最新价，并以接管时可用价格作为后续管理
的起始参考。此时页面盈亏不等同于交易所历史真实成本盈亏。

## 风险边界

- 当前按整笔交易所仓位接管，不提供部分数量接管。
- 接管不会改变交易所现有仓位数量，但启动后的源码可以提交真实订单。
- 杠杆会影响交易所收益率和风险理解，但价格止损距离仍必须由源码明确计算，不能只依赖收益率。
- Binance 单向持仓模式降低了方向歧义，但仍需防止其他客户端同时操作同一品种。
- 交易所快照、网络和订单回报存在延迟，页面数据不能替代交易所端最终状态。
- 在实盘前先用小额仓位验证启动、退出、同步、自动停止和异常恢复的完整闭环。
