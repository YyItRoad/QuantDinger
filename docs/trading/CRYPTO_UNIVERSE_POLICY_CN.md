# 数字货币币种池规则（简化版 V1）

更新日期：2026-08-31

## 1. 这套规则解决什么问题

币种池只解决三件事：

1. 哪些币值得持续关注；
2. 哪些币允许交易；
3. 不同类型的币最多承担多少风险。

币种所在层级代表风险和交易权限，不代表未来一定上涨。

## 2. 池子怎么分

| 池子 | 代码 | 用途 | 是否允许交易 |
| --- | --- | --- | --- |
| 核心池 | `crypto-core` | 成熟、流动性最好，适合主要仓位 | 允许现货；合约需单独批准 |
| 重点池 | `crypto-focus` | 主流或值得重点跟踪，但稳定性低于核心池 | 允许现货；合约严格限制 |
| 新兴池 | `crypto-emerging` | 有潜力但历史短、波动大 | 只允许小仓位现货 |
| 观察池 | `crypto-watch` | 暂未达标或正在观察 | 不允许新开仓 |
| 限制池 | `crypto-restricted` | 发生重大风险、退市或数据异常 | 只允许撤单和减仓 |
| 资金资产池 | `crypto-cash` | USDT、USDC 等获准稳定币 | 只作为计价、结算或保证金资产 |

当前 CoinGecko 市值 Top-100 可以作为候选名单，但不能直接作为交易白名单。

## 3. 币种池列表怎么展示

日常使用的币种池列表只展示四列：

| 列名 | 说明 |
| --- | --- |
| 币种 | 使用统一的币种简称，例如 `BTC`、`ETH`；这里只表示资产，不表示具体交易所或交易对 |
| 所属池 | 当前所属的核心池、重点池、新兴池、观察池、限制池或资金资产池 |
| 主要理由 | 用一句话说明本次归类最重要的依据，例如流动性达标、上市时间较短或发生安全事件 |
| 决策 | 直接说明当前允许采取的动作，不在这一列重复详细指标 |

示例：

| 币种 | 所属池 | 主要理由 | 决策 |
| --- | --- | --- | --- |
| BTC | 核心池 | 市值、流动性和市场成熟度均达标 | 正常交易 |
| SOL | 重点池 | 市场活跃，但风险高于核心资产 | 控制仓位 |
| SUI | 新兴池 | 成交活跃，但历史较短、波动较大 | 仅小仓位现货 |
| `WATCHCOIN` | 观察池 | 暂未满足成交额或观察期要求 | 禁止开仓 |
| `RISKCOIN` | 限制池 | 存在安全、退市或交易异常风险 | 只允许减仓 |
| USDT | 资金资产池 | 用作计价和结算资产 | 监控脱锚风险 |

“决策”列统一使用少量标准表述：`正常交易`、`控制仓位`、`仅小仓位现货`、`禁止开仓`、`只允许减仓`、`暂停交易`、`监控脱锚风险`。

市值、成交额、交易所数量、上市时间等详细数据保留在后台作为归类依据，不放入日常列表。

## 4. 只看五项指标

每个币只评估以下五项：

1. **市值**：规模是否足够，是否容易被少量资金操纵；
2. **成交额**：在我们实际使用的交易所里是否有持续成交；
3. **交易所覆盖**：是否在多个获准交易所正常交易；
4. **上市时间**：是否经历过足够长的市场检验；
5. **风险事件**：是否存在攻击、停链、退市、无限增发、重大解锁或监管风险。

点差、盘口深度和交易所状态仍要在每次下单前检查，但不再设计复杂的日常评分表。

## 5. 入选条件

以下金额均指获准交易所中合格现货交易对的 30 日平均日成交额。

| 条件 | 核心池 | 重点池 | 新兴池 |
| --- | ---: | ---: | ---: |
| 市值排名 | Top-20 | Top-75 | Top-200 或人工批准 |
| 30 日平均日成交额 | ≥ 2 亿美元 | ≥ 5,000 万美元 | ≥ 1,000 万美元 |
| 正常交易的获准交易所 | ≥ 3 家 | ≥ 2 家 | ≥ 1 家 |
| 上市时间 | ≥ 2 年 | ≥ 1 年 | ≥ 90 天 |
| 重大未解决风险 | 无 | 无 | 无 |

所有条件必须同时满足，不能用高市值弥补低成交额。

首次入选最高只能进入重点池。连续两个月符合核心池条件，才可以升级为核心池。

## 6. 哪些资产不参加普通排名

以下资产单独处理：

- 稳定币进入资金资产池，不作为方向性投资标的；
- 包装币、跨链币和质押凭证合并到原生资产计算风险；
- 杠杆代币、反向代币默认进入限制池；
- 无法确认主网、合约地址或项目身份的币进入观察池；
- 账户所在地区不允许交易的币进入限制池。

例如，BTC 和包装 BTC 不得分别获得两份仓位额度。

## 7. 升级、降级和移除

### 升级

- 连续两个月满足更高层条件；
- 期间没有重大风险事件；
- 在每月评审时生效。

### 降级

出现以下任一情况，先禁止加仓，再降到下一层：

- 任一入选条件连续 3 天不满足；
- 成交额比前 30 日下降 50% 以上；
- 正常交易的获准交易所数量减少；
- 未来 30 日有大额代币解锁；
- 项目治理、团队或监管风险明显增加。

### 移入观察池

- 连续 10 天达不到新兴池条件；
- 关键行情数据连续 24 小时无法验证；
- 没有可以正常退出的交易所；
- 无法确认供应量、合约地址或资产身份。

### 立即进入限制池

以下情况不等待日终评审：

- 交易所暂停交易或发布退市通知；
- 主网停摆、严重重组或关键合约被攻击；
- 出现无限增发、私钥泄露或重大资产缺口；
- 价格、成交额或盘口明显异常，无法形成可靠价格；
- 继续交易可能违反账户或地区限制；
- 计价稳定币脱锚超过 1% 并持续 30 分钟。

## 8. 交易约束

以下是保守型默认上限，实际交易时还要服从更严格的策略级和账户级风控。

| 约束 | 核心池 | 重点池 | 新兴池 |
| --- | ---: | ---: | ---: |
| 单币最大仓位 | 15% NAV | 8% NAV | 2% NAV |
| 该层总仓位 | 60% NAV | 30% NAV | 10% NAV |
| 单笔最大计划损失 | 0.75% NAV | 0.50% NAV | 0.25% NAV |
| 现货 | 允许 | 允许 | 允许 |
| 永续合约 | 单独批准 | 原则上不开，特殊批准 | 禁止 |
| 最大杠杆 | 2 倍 | 1.5 倍 | 不允许杠杆 |

共同规则：

1. 新兴池只能使用限价单；
2. 单笔订单不能超过当前盘口可见深度的 10%；
3. 下单前必须检查交易状态、点差、深度、最小下单额和价格精度；
4. 同一币在不同交易所、不同交易对和包装形式下的仓位必须合并计算；
5. 观察池禁止开仓，限制池只允许撤单和减仓；
6. 没有明确止损或无法估算最大损失时，不允许开仓。

## 9. 已持仓币被移除怎么办

| 情况 | 处理方式 |
| --- | --- |
| 普通降级 | 立即停止加仓，5 天内降至新层仓位上限 |
| 移入观察池 | 立即停止加仓，原则上 3 天内有序退出 |
| 安全、退市或合规事件 | 立即撤单，在可成交和合法的前提下优先降低风险 |
| 暂停交易或没有可靠价格 | 停止自动下单，等待恢复后由人工决定如何减仓 |

不得为了按时退出而忽略滑点、盘口深度或交易状态，也不能把无法退出的仓位从风险报表中隐藏。

## 10. 检查频率

| 频率 | 检查内容 |
| --- | --- |
| 实时 | 交易状态、盘口、重大风险事件 |
| 每日 | 市值、成交额、交易所数量和异常数据 |
| 每月 | 正式升级、新增成员和池子快照 |

每次变化只需记录：原层级、新层级、原因、生效时间和批准人。

## 11. 建议的上线顺序

1. 连续 30 天只计算和观察，不影响交易；
2. 接入模拟交易，验证仓位限制和移除流程；
3. 先开放核心池现货；
4. 再考虑重点池和新兴池现货；
5. 永续合约最后单独评审。

## 12. 与 QuantDinger 的衔接

- 使用完整标的格式，例如 `Crypto:BTC/USDT@okx:spot`；
- 资产入池后，具体交易所和交易对仍需单独通过交易工具检查；
- 回测必须使用当时的历史池快照，避免使用今天的成员回测过去；
- QuantDinger 当前不在 Strategy API V2 回测中模拟 Crypto 资金费用，因此永续回测不能直接代表实盘净收益；
- 币种池只提供交易资格和仓位上限，不能绕过人工确认、账户权限、模拟交易开关和服务端风控。

## 13. 还需要你确认的三个选择

1. 核心、重点、新兴的总仓位是否采用 `60% / 30% / 10%`；
2. 第一阶段是否只开放现货；建议是；
3. 是否先只支持 USDT 计价；建议先只支持一种计价资产，稳定后再增加 USDC。
